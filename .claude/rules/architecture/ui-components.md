# UI コンポーネント配置

コンポーネントディレクトリはフラットに並べず、サブディレクトリで分類する。

---

## 分類軸

**ドメイン知識の有無** と **利用スコープ** の 2 軸でコンポーネントを分類する。

---

## サブディレクトリ

### `primitives/` - 汎用 UI 部品

ドメイン層の型 (Value Object, Entity のインターフェース) に一切依存しない再利用可能なコンポーネント。

- どのページ・機能からでも利用可能
- props はプリミティブ型 (`string`, `number`, `boolean` 等) またはコンポーネント固有の型のみ
- 例: ボタン、入力フィールド、アイコン、モーダル、タグリスト

### `{feature}/` - 機能特化コンポーネント

特定の機能ドメインに特化したコンポーネント。ドメイン層の型に依存する。

- サブディレクトリ名は機能ドメイン名とする
- props にドメインの Value Object や Entity のインターフェースを受け取る
- 機能ドメインが増えるたびにサブディレクトリを追加する
- 例: ダッシュボード機能のカード群、設定画面のエディター群

### `layout/` - レイアウト・ナビゲーション

アプリ全体のレイアウトやナビゲーションに関するコンポーネント。

- ルートレイアウトやドキュメントヘッドなど、ページ構造を制御する
- ステップナビゲーション、サイドバーなどのアプリ全体のナビゲーション

---

## 配置判断フロー

1. ドメイン層の型に依存するか? → Yes: `{feature}/`
2. アプリ全体のレイアウト・ナビゲーションに関するか? → Yes: `layout/`
3. 上記いずれでもない → `primitives/`

---

## ディレクトリ構成例

```
components/
├── primitives/
│   ├── button/
│   ├── input-field/
│   ├── icon/
│   └── modal/
├── {feature-a}/
│   ├── summary-card/
│   └── detail-editor/
├── {feature-b}/
│   └── timeline-viewer/
└── layout/
    ├── app-header/
    └── step-navigation/
```
